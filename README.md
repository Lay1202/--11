# 과제 11: 삽입 정렬과 쉘 정렬의 성능 비교

## 1. 실행 방법

```
gcc -O2 -o sort_compare sort_compare.c
./sort_compare
```

- 난수 시드는 `srand(12345)`로 고정하여 같은 결과를 재현할 수 있습니다.
- 각 데이터 크기마다 원본 배열을 한 번 생성하고, 세 알고리즘은 모두 그 원본의 복사본으로 정렬합니다.
- 비교 횟수는 `a[j-h] > tmp`처럼 데이터 값끼리 비교할 때만 1회씩 셉니다. 반복문 조건 검사는 세지 않습니다.
- 정렬 후 `is_sorted()`로 오름차순 여부를 검증합니다.

## 3. 분석

### 3.1 데이터 크기 증가에 따른 비교 횟수 변화

삽입 정렬은 n이 2배가 될 때마다 비교 횟수가 거의 정확히 4배가 됩니다. 1,000 → 16,000 전체로 보면 248,805에서 63,620,807로 약 255.7배 늘었고, 이는 16² = 256과 거의 일치합니다. 지수로 환산하면 약 n^2.0입니다. 무작위 데이터에서 삽입 정렬의 기대 비교 횟수가 약 n²/4라는 이론값과도 맞습니다(n=1,000이면 250,000, n=20,000이면 100,000,000이고 측정값은 248,805와 99,865,490).

쉘 정렬은 n이 2배가 될 때 증가 배율이 2.3~2.6배 정도입니다. 16배 증가한 구간 전체로 환산한 지수는 기본 간격이 약 n^1.28, Knuth가 약 n^1.26이며, 삽입 정렬의 n^2.0보다 훨씬 완만합니다. 그래서 n이 커질수록 격차가 벌어집니다.

### 3.2 삽입 정렬과 쉘 정렬의 성능 차이

n=1,000에서는 쉘 정렬이 삽입 정렬보다 17~18배 적게 비교하지만, n=20,000에서는 160~175배까지 차이가 납니다. 두 알고리즘의 비교 횟수 증가율(약 n^2.0 대 약 n^1.27)이 다르기 때문에, 이 격차는 n에 따라 계속 커집니다.

원인은 삽입 정렬에서 원소 하나가 제자리를 찾을 때 한 칸씩만 이동한다는 점에 있습니다. 무작위 배열에서는 원소가 평균적으로 i/4칸쯤 이동해야 하므로 비교가 n²에 비례해 늘어납니다. 쉘 정렬은 처음에 큰 간격으로 멀리 떨어진 원소들을 한 번에 크게 이동시켜 역전된 쌍을 많이 해소합니다. 이 과정을 거치면 배열이 "거의 정렬된 상태"에 가까워집니다. 삽입 정렬은 거의 정렬된 입력에서 원소당 이동 거리가 짧아 비교 횟수가 O(n)에 가까워집니다. 최종 단계인 h=1 패스는 일반 삽입 정렬과 같은 코드이지만, 앞 단계들이 배열을 미리 정리해 둔 덕분에 훨씬 적은 비교로 끝납니다.

### 3.3 기본 간격과 Knuth 수열의 성능 차이

모든 크기에서 Knuth 수열이 기본 간격(n/2, n/4, …, 1)보다 비교 횟수가 적었고, 감소율은 7.7~13.5% 범위입니다. 삽입 정렬과의 격차에 비하면 작지만 일관된 차이입니다. 차이가 크지 않은 이유는 두 방식 모두 간격이 대략 등비수열로 줄어드는 구조이고, 비교 횟수의 대부분이 이 구조에서 결정되기 때문입니다. 두 수열의 성장 지수 차이도 n^1.28과 n^1.26으로 작습니다.

감소율이 데이터 크기에 따라 7~13%로 오르내리는 것도 주목할 만합니다. 특히 n=16,000에서는 13.5%로 가장 크고, n=20,000에서는 8.0%로 줄었습니다. 기본 간격은 n에서 출발하므로 n의 약수 구조에 따라 간격 열이 달라지고, 이에 따라 성능이 달라집니다. 반면 Knuth 간격은 n에 덜 민감하게 동작합니다. 다만 이 실험은 크기별로 난수 배열 하나씩만 사용했기 때문에, 몇 %p의 차이는 데이터 자체의 편차일 수도 있습니다. 일관되게 Knuth가 앞섰다는 점은 확실하지만, 정확한 감소율 수치는 여러 시드의 평균으로 확인해야 더 신뢰할 수 있습니다.

### 3.4 간격 수열이 성능에 영향을 미치는 이유

**(1) 간격이 정렬 단계 사이에서 얼마나 정보를 섞어 주는가**

h 간격 정렬은 배열을 h개의 부분 배열(인덱스를 h로 나눈 나머지가 같은 원소들)로 나누어 각각 삽입 정렬하는 것과 같습니다. 어떤 패스에서 정렬된 원소들이 다음 패스에서 다시 같은 부분 배열에만 묶이면, 새 패스가 얻는 정보가 적습니다. 반대로 간격이 서로 잘 섞이면 각 패스가 다른 부분 배열의 원소들을 서로 비교하게 되어 정렬이 빠르게 진행됩니다.

**(2) 기본 간격의 약점: 간격들이 서로 약수·배수 관계**

기본 간격은 n/2, n/4, n/8…이어서 서로 배수 관계인 경우가 많습니다. 예를 들어 n=16,000이면 8000, 4000, 2000, 1000, 500, 250, 125까지 모두 앞 간격의 약수입니다. 이 구간에서는 이전 패스에서 같은 부분 배열에 있던 원소들이 다음 패스에서도 같은 부분 배열에 머뭅니다. 그 결과 인덱스의 홀짝이 다른 원소끼리 비교될 기회가 늦게야 옵니다. 이 상호작용은 마지막 h=1 패스에서야 일어나며, 그때 일이 상대적으로 많이 남아 있게 됩니다.

**(3) Knuth 수열의 강점: 서로 섞이는 간격과 적절한 감소 비율**

Knuth 수열(1, 4, 13, 40, 121, …)은 약 3배씩 줄어들고, 인접한 간격이 2의 거듭제곱처럼 공통 인수를 공유하는 구조가 아닙니다(인접한 두 간격은 서로소입니다). 그래서 앞 패스에서 정리된 정보가 다음 패스에서 다른 부분 배열의 원소와 섞입니다. 또한 3배 가까이 줄어드는 비율은 패스당 충분한 정렬 효과를 내면서도 패스 수를 줄이는 균형점에 해당합니다. n=20,000에서 기본 간격은 14번의 패스를 수행하지만 Knuth는 9번만 수행합니다(1, 4, 13, 40, 121, 364, 1093, 3280, 9841). 패스마다 최소한 n−h번의 비교가 필요하므로 패스 수가 적다는 것은 고정 비용이 적다는 뜻입니다.

**(4) 이론적 배경**

기본 쉘 수열의 최악 시간복잡도는 O(n²)로 알려져 있고, Knuth 수열은 O(n^1.5)로 알려져 있습니다. 이번 실험은 무작위 데이터의 평균적인 경우이므로 두 수열의 지수가 1.26~1.28로 비슷하게 나왔지만, 간격 수열의 선택이 최악의 경우를 크게 바꿀 수 있다는 점이 쉘 정렬에서 간격 수열이 중요한 이유입니다.

## 4. 결론

- 삽입 정렬의 비교 횟수는 n²/4에 거의 일치하며, n이 2배가 되면 4배로 증가합니다.
- 쉘 정렬은 n이 2배가 될 때 약 2.3~2.6배만 증가하고, n=20,000에서는 삽입 정렬보다 160배 이상 적은 비교로 정렬됩니다.
- Knuth 수열은 모든 크기에서 기본 간격보다 약 8~14% 적은 비교 횟수를 보였습니다. 이 차이는 간격 사이의 약수 관계를 피하고 패스 수를 줄인 데서 비롯된 것으로 해석됩니다.
- 간격 수열의 선택은 상수 배 수준의 차이를 만드는 것에 그치지 않고, 이론적으로는 최악의 경우 성능 자체(O(n²) 대 O(n^1.5))를 바꿀 수 있으므로 쉘 정렬 설계에서 핵심 요소입니다.
